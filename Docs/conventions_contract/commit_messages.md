 2. Commit Messages

  Use Conventional Commits: feat: add search endpoint for weather API. Write in the imperative — the message must
  make sense after "This commit will…". Keep the subject under 50 characters, lowercase after the colon, no full
  stop.

  Types are feat, fix, docs, refactor, test, chore, ci. Add a body after a blank line when the change needs
  justifying, and use it to explain why, not what — the diff already shows what.

  One logical change per commit; never mix a bugfix with a refactor. No fix, update, wip or asdf — they carry no
  information when you look back. Issue links (Closes #42) go in the pull request description, not in each
  commit.
